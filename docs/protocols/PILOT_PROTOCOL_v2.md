# Jev 价值试点方案 v2（预注册）

版本：v2，2026-09-24。本文件在任何 v2 付费调用、任何 v2 评估/新型数据生成之前冻结。
前序：`docs/jev/PILOT_PROTOCOL_v1.md`（v1 结果全部如实保留，下文第 0 节披露）。
根因分析产物：`artifacts/jev_pilot_rootcause/analysis.json`（脚本 `hydrojev/benchmarks/jev_pilot_rootcause.py`，离线、0 次付费调用；P2 只用 train split）。

**诚信边界（对所有结论生效）**：v2 的改动只针对 v1 暴露的**评测设计缺陷和呈现偏差**，不针对结果调参。
不在测试集上调任何东西；不削弱基准（R1 冻结原样，R2 获得与 Jev 相同的新增证据字段）；不挑子集（LOSO 轮换全部子类型）；
所有终点、阈值、统计方法在此预注册；无论输赢，全部结果（含原始未校准 Jev）都报告。不能保证 Jev 获胜——
本方案保证的是：如果 Jev 真有优势，它能被公平地测出来。

## 0.1 根因（离线复算，数值见 analysis.json）

**P1**
1. **R2 基准是样本内的**：R2 在 156 个 dev 候选上拟合后又在其中 30 个上打分，AUC 0.951 是训练集表现。
   按攻击片段分组的 blocked-OOF R2：debug-30 AUC 0.831（全 dev 0.83）。公平比较下 Jev 领先：
   R1−R2oof +0.062 [−0.10, 0.225]，R2−R2oof +0.087 [−0.062, 0.25]；vs Mahalanobis +0.033 / +0.058；n=30 下 CI 均含 0。
2. **R1 在操作点上是信息天花板**：dev 上 R1 的 TPR=1.000、FPR=0.193，它的良性误报与真报警的违规检查组合完全相同
   （仅 junction-pressure+tank-level-change 组合有区分度：29 TP vs 1 FP）。在 R1 已经全召回的前提下，
   任何"否决器"都无法在同一证据上超过 R1 的 balanced accuracy。Round 1 在阈值 0.6 恰好复现 R1。
   v1 把"balanced ≥ R2/R1"设为主终点，是一个结构上赢不了的终点，这是方案设计缺陷，不是 Jev 缺陷。
3. Round 2 的基率提示把 junction-pressure-only 窗口（dev 外 n=19，攻击占 68.4%）压到 0.42–0.55，错了 3/6。

**P2**
1. **呈现偏差**：`system` 文本写了攻击者能力，而一致（未违规）的控制逻辑检查仍附带 "issue" 明细
   （含此类明细的比例：cyber 0.70 / physical 0.90 / normal 0.82 / sensor 0.94——非 cyber 类反而更多）。
   Jev 的平均概率：cyber 0.775、physical 0.122、normal 0.011、sensor 0.092。
2. **没有校准**：无标签批校准（Batch Calibration，Zhou et al. ICLR 2024；先验偏移校正，Saerens 2002）后
   Jev 8/12，macro-F1 0.657；LOO 校准相同；R1 5/12（0.408）。Top-2 准确率 0.75。但 normal 常被四舍五入到 0.00，校准无法恢复。
3. **缺少带符号的判别量**：系统需求残差的符号几乎完美区分 physical（负号比例 0.0，中位 z=+2.88）与其他类，
   但 state 中只以绝对偏差形式出现。
4. **R2 在已见子类型上强、在未见子类型上崩**：LOSO 未见子类型召回 burst 0（整类被移除）、demand_rise 0.053、
   pump_off 0.034、overpump 0.048、operator_switch 0.0，而已见时 0.67–1.0。
   标签稀缺曲线：R2 macro-F1 在 k=1/2/4/8/16 per class 时为 0.42/0.52/0.66/0.83/0.91（debug-12），
   与校准后 Jev（0.657）的交叉点 k≈4。
5. 注意：v1 的判据示例覆盖了两个 cyber 子类型，所以 v1 LOSO 对 Jev 并非真正的 OOD；v2 判据改为类别级通用定义。

**结论**：Jev 真实的相对优势在 (a) 排序（阈值无关 AUC）、(b) 未见子类型/分布外、(c) 标签稀缺。
v1 的主终点恰好设在它的劣势区（有全标签的同分布、操作点 vs 天花板规则）。v2 把主终点移到这些方面，并修正呈现偏差。

## 1. P1 v2（BATADAL，单次测试集运行）

- **冻结问题**：round 2（sha `efad9039…`）。选择依据是 v1 预声明的"debug AUC 更高者"规则（0.918 > 0.893）。
  Round 1 作为纯零样本备选，不再调用。
- **无新 debug 调用**。操作阈值预注册为 round-2 debug-30 响应上的 Youden J 点：**t = 0.42**（debug TPR 0.933，FPR 0.20）。
- **测试集运行**：`artifacts/jev_pilot_p1/requests_r2/test_dataset` 的 107 个候选窗口（64 攻击），每窗口 1 次，
  stage `p1_test_r2`，tag `p1_test_r2_test_dataset_{raw_index:05d}`。测试集只评估这一次。
- **比较器密封**：`prepared.json` 中 test 的 R1/R2/检测器数值在 Jev 测试运行完成前不读取。

**主终点**（配对 bootstrap 2000 次，95% CI，α=0.05）：
- H1a：测试集 ROC-AUC，Jev > R2（dev 训练，out-of-sample 已存 `r2_probability`）。
- H1b：测试集 ROC-AUC，Jev > Mahalanobis（预先指定为 dev 上最强的单一检测器，dev AUC 0.891）。
- 两个主终点用 Holm 校正。判定"胜"需要校正后 CI 下限 > 0。

**次终点**：
- 相对 7 个先前检测器的 AUC 差值（Holm 校正）。
- 阈值 0.42 下的 balanced accuracy vs R1/R2。**预先声明不主张对 R1 获胜**（信息天花板）；
  R1 是二值的，其 AUC 即 balanced accuracy，与连续分数比较不对等，仅作说明。
- R1 阳性集合内的重排序：Jev 在 R1 阳性内的 AUC（R1 本身在该集合内无区分度 = 0.5）。
- 测试集上的标签稀缺 R2 曲线（k=1…32，按片段分组）。
- 可选：12–20 次重复一致性调用。

**口径**：R1/R2 是"同一 HydroJEV 证据的消融"，不是外部前人方法；前人方法是 7 个检测器。

## 2. P2 v2（EPANET 原因判别）

新模块 `hydrojev/benchmarks/jev_pilot_p2v2.py`，import v1 生成器，**不修改 v1 行为**。
产物目录 `artifacts/jev_pilot_p2v2/`，所有 split 使用新种子（与 v1 不重叠）。

### 2.1 去偏呈现（冻结判据前完成）
- `detail` 只对**违规**检查输出；一致的检查只给 status/statistic/threshold/基率/meaning。
- `system` 文本中性化：删除攻击者能力句，对称地列出 4 个原因族。
- 增加带符号判别量：系统需求残差方向与 z、压力扩散模式与符号、各水箱残差符号、印证通道数。
  **同样的字段加入 R2 特征**（公平性）。R1 冻结不动。
- 判据改为类别级通用定义，不含子类型示例：
  - cyber_attack = 被掩盖的操纵：遥测与物理相关测量或孪生矛盾；
  - normal_transient = 未被掩盖的运行：包括遥测诚实的操作员切换、需求变化；
  - physical_fault = 真实水力变化，遥测相互一致，但孪生无法解释；
  - sensor_fault = 单通道偏差，无水力后果。
- 指令加入"对四类使用均匀先验，每类给出非零概率"，保证 normal 不被四舍五入为 0.00。
- 泄漏扫描沿用 `_STATE_LEAK_TOKENS`。
- **冻结顺序**：判据/问题/state 格式哈希写入本文件的附录 → 然后才生成 eval 和新型子类型数据。

### 2.2 校准与融合
- 主：**归纳式无标签校准**。在约 24 个 train 窗口上调用 Jev，不看标签，取平均概率向量 π；
  评估时 argmax(p/π)。
- 次：转导式 LOO 校准（用同一评估集其余窗口的均值，不看标签）。
- 始终同时报告原始 Jev。
- 次：Jev⊗R2 几何均值融合，权重 0.5，预先固定。

### 2.3 数据与评估
- Debug：12 个 train 窗口（3/类），用于检查去偏后格式是否正常。只检查格式与异常行为
  （>50% insufficient_evidence，或单一类别 >90%），不据此调判据；允许 1 轮 12 次的应急修正，并须披露。
- **E1 同分布 C-Town**：40 个窗口（10/类，新种子）。物理类增加第二个子类型（见下），使物理类 LOSO 有意义。
- **LOSO 轮换**：复用 E1 的 Jev 预测（0 次额外调用），对**所有**子类型轮换；R2 每次在去掉该子类型的 train 上重训。
  burst 的"整类移除"单独报告。
- **E2 新型子类型（可选，判据冻结后才实现）**：约 40 个窗口。
  - cyber：pump_on_spoofed_off（强制开泵，上报 S/F 保持 0）；overpump_level_replay（上报液位回放 24 h 前）。
  - physical：pump_degradation（泵转速/扬程曲线下降）；pipe_blockage（部分关阀：局部损失或粗糙度）。
  - normal：demand_pattern_shift（日模式平移 1–3 h）。
  - sensor：gain_error（读数 ×(1+g)）；spikes。
  - 排除物理上无法区分的事件（消防用水、检修关阀）。
  - R2 用 train 全部标签训练，对 E2 为未见子类型。
- **标签稀缺曲线**（E1）：R2 在 k=1,2,4,8,16,40 per class 下的 macro-F1（200 次抽样），报告交叉点 k*。
- Net3 零样本：可选，预算允许时 24 窗口。

### 2.4 预注册假设
- **H1（主）**：OOD（LOSO 汇总 + E2）macro-F1，校准 Jev > R2 且 > R1，配对 bootstrap CI 下限 > 0（Holm 校正两比较）。
- **H2**：交叉点 k* ≥ 4（Jev 在每类 ≤4 个标签的场景下优于 R2）。
- **H3（报告，不主张）**：同分布全标签下 R2 预计优于 Jev，如实报告。
- **H4**：同分布 C-Town，校准 Jev ≥ R1 + 0.10 macro-F1。
- 评估集比较器指标在 Jev 运行完成前密封（v1 的 prepare 会打印比较器，v2 改为写入密封文件）。

## 5. 局限
- P1 是 debug 选出的问题与阈值（已披露），测试集只跑一次；n=107 时可检出的 ΔAUC 约 0.06。
- P2 为合成 EPANET 场景；operator_switch 与未掩盖的命令注入在物理上不可区分，因此以"是否掩盖"定义类别。
- 新型子类型由作者设计，存在设计者偏好风险；判据先冻结再实现可缓解但无法消除。
- 两位小数的概率舍入限制了校准精度。
